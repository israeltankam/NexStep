Migration local → cloud

Guide de migration SQLite vers PostgreSQL

Ce guide explique comment passer de la base locale data/local.db à une base PostgreSQL, par exemple Supabase, avant hébergement sur Streamlit Cloud.

1. Préparer PostgreSQL

  1. Créer un projet PostgreSQL ou Supabase.
  2. Dans Supabase, ouvrir le projet puis cliquer sur Connect.
  3. Copier une URL PostgreSQL. Pour la migration, prendre de préférence l'URL Direct connection. Si le réseau local refuse l'IPv6, prendre l'URL Session pooler.
  4. Conserver cette URL dans un endroit sûr. Elle contient ou contiendra le mot de passe de base de données.

Référence officielle: Supabase - Connect to your database.

2. Comprendre et compléter l'URL Supabase

Oui: quand le guide affiche USER:PASSWORD, il faut remplacer ces valeurs par celles données par Supabase. Le plus simple est toutefois de ne pas reconstruire l'URL à la main: copie l'URL complète fournie par Supabase, puis remplace uniquement le placeholder du mot de passe.

Cas le plus courant: Direct connection

Supabase peut afficher une URL de ce type:

postgresql://postgres:[YOUR-PASSWORD]@db.abcdefghijklmnopqrst.supabase.co:5432/postgres

Tu gardes postgres, le host, le port et la base postgres. Tu remplaces seulement [YOUR-PASSWORD] par le mot de passe de la base Supabase:

postgresql://postgres:MON_MOT_DE_PASSE_SUPABASE@db.abcdefghijklmnopqrst.supabase.co:5432/postgres

Cas pooler Supabase

Supabase peut aussi fournir une URL de pooler ressemblant à ceci:

postgresql://postgres.PROJECT_REF:[YOUR-PASSWORD]@aws-REGION.pooler.supabase.com:5432/postgres

Dans ce cas, tu gardes aussi l'utilisateur complet postgres.PROJECT_REF. Là encore, tu remplaces seulement [YOUR-PASSWORD].

Si ton mot de passe contient des caractères spéciaux comme @, #, :, / ou un espace, utilise idéalement l'URL copiée depuis Supabase ou encode ces caractères dans l'URL. Exemple: @ devient %40.

Dans PowerShell, mets toujours l'URL entre guillemets.

3. Installer les dépendances

pip install -r requirements.txt

La migration utilise psycopg, déjà listé dans requirements.txt.

4. Tester sans écrire

python scripts/migrate_sqlite_to_postgres.py --dry-run

Le dry-run lit SQLite et affiche les volumes par table. Aucune donnée n'est écrite dans PostgreSQL.

5. Exploiter l'URL Supabase pour migrer les données

L'URL obtenue de Supabase est utilisée ici dans l'option --postgres-url. C'est cette commande qui copie les données de data/local.db vers PostgreSQL:

python scripts/migrate_sqlite_to_postgres.py --sqlite-path data/local.db --postgres-url "postgresql://postgres:MON_MOT_DE_PASSE_SUPABASE@db.abcdefghijklmnopqrst.supabase.co:5432/postgres" --apply

Le script crée les tables si besoin, insère les données dans l'ordre correct et ignore les lignes déjà présentes avec le même identifiant.

Après exécution, le rapport affiche les volumes SQLite, les lignes insérées, les lignes ignorées car déjà présentes, et les volumes PostgreSQL.

6. Exploiter la même URL dans Streamlit Cloud

La même URL PostgreSQL, ou l'URL pooler recommandée pour l'exécution cloud, doit ensuite être placée dans les secrets Streamlit Cloud sous le nom DATABASE_URL. NexStep et ses scripts utilisent ce nom de variable comme point d'entrée standard vers la base cloud.

Dans Streamlit Cloud, ouvrir App settings, puis Secrets, et ajouter:

DATABASE_URL="postgresql://postgres:MON_MOT_DE_PASSE_SUPABASE@db.abcdefghijklmnopqrst.supabase.co:5432/postgres"
APP_PIN_PEPPER="une-valeur-longue-et-secrete"
APP_ENV="cloud"

Si une URL est fournie sous la forme postgresql+psycopg://..., le script de migration la convertit automatiquement pour psycopg.

Ne pas publier ces valeurs dans Git, dans un PDF partagé ou dans une capture d'écran.

7. Vérifier

  • Le nombre de leads PostgreSQL doit être au moins égal au nombre SQLite.
  • Les commentaires legacy doivent rester présents.
  • Un agent doit pouvoir se connecter et voir sa prochaine action.
  • L'admin doit voir les organisations, utilisateurs, imports et logs.

SQLite to PostgreSQL Migration Guide

Copy the PostgreSQL URL from Supabase, then replace [YOUR-PASSWORD] with the database password. Use that completed URL in --postgres-url to migrate the local SQLite data. Then store the same URL, or the recommended runtime pooler URL, as DATABASE_URL in Streamlit Cloud secrets, together with APP_PIN_PEPPER and APP_ENV=cloud.
