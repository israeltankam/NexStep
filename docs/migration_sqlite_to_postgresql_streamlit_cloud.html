Migration local → cloud

Guide de migration SQLite vers PostgreSQL

Ce guide explique comment passer de la base locale data/local.db à une base PostgreSQL, par exemple Supabase, avant hébergement sur Streamlit Cloud.

1. Préparer PostgreSQL

  1. Créer un projet PostgreSQL ou Supabase.
  2. Dans Supabase, ouvrir le projet puis cliquer sur Connect.
  3. Copier une URL PostgreSQL. Pour la migration, prendre de préférence l'URL Direct connection. Si le réseau local refuse l'IPv6, prendre l'URL Session pooler.
  4. Conserver cette URL dans un endroit sûr. Elle contient ou contiendra le mot de passe de base de données.

Référence officielle: Supabase - Connect to your database.

2. Comprendre et compléter l'URL Supabase

Oui: quand le guide affiche USER:PASSWORD, il faut remplacer ces valeurs par celles données par Supabase. Le plus simple est toutefois de ne pas reconstruire l'URL à la main: copie l'URL complète fournie par Supabase, puis remplace uniquement le placeholder du mot de passe.

Cas le plus courant: Direct connection

Supabase peut afficher une URL de ce type:

postgresql://postgres:[YOUR-PASSWORD]@db.abcdefghijklmnopqrst.supabase.co:5432/postgres

Tu gardes postgres, le host, le port et la base postgres. Tu remplaces seulement [YOUR-PASSWORD] par le mot de passe de la base Supabase:

postgresql://postgres:MON_MOT_DE_PASSE_SUPABASE@db.abcdefghijklmnopqrst.supabase.co:5432/postgres

Cas pooler Supabase

Supabase peut aussi fournir une URL de pooler ressemblant à ceci:

postgresql://postgres.PROJECT_REF:[YOUR-PASSWORD]@aws-REGION.pooler.supabase.com:5432/postgres

Dans ce cas, tu gardes aussi l'utilisateur complet postgres.PROJECT_REF. Là encore, tu remplaces seulement [YOUR-PASSWORD].

Si ton mot de passe contient des caractères spéciaux comme @, #, :, / ou un espace, utilise idéalement l'URL copiée depuis Supabase ou encode ces caractères dans l'URL. Exemple: @ devient %40.

Dans PowerShell, mets toujours l'URL entre guillemets.

3. Installer les dépendances

pip install -r requirements.txt

La migration utilise psycopg, déjà listé dans requirements.txt.

4. Tester sans écrire

python scripts/migrate_sqlite_to_postgres.py --dry-run

Le dry-run lit SQLite et affiche les volumes par table. Aucune donnée n'est écrite dans PostgreSQL.

5. Exploiter l'URL Supabase pour migrer les données

L'URL obtenue de Supabase est utilisée ici dans l'option --postgres-url. C'est cette commande qui copie les données de data/local.db vers PostgreSQL:

python scripts/migrate_sqlite_to_postgres.py --sqlite-path data/local.db --postgres-url "postgresql://postgres:MON_MOT_DE_PASSE_SUPABASE@db.abcdefghijklmnopqrst.supabase.co:5432/postgres" --apply

Le script crée les tables si besoin, insère les données dans l'ordre correct et ignore les lignes déjà présentes avec le même identifiant.

Après exécution, le rapport affiche les volumes SQLite, les lignes insérées, les lignes ignorées car déjà présentes, et les volumes PostgreSQL.

6. Exploiter la même URL dans Streamlit Cloud

Dans Supabase, cliquer sur Connect, choisir Session pooler et copier l'URL du port 5432. Ce mode est adapté à une application Streamlit persistante et fonctionne sur les réseaux IPv4 de Streamlit Cloud.

Remplacer uniquement [YOUR-PASSWORD], puis placer l'URL complète dans les secrets Streamlit Cloud sous le nom DATABASE_URL. Les trois clés ci-dessous doivent être à la racine du fichier TOML, sans section [database].

Dans Streamlit Cloud, ouvrir App settings, puis Secrets, et ajouter:

DATABASE_URL="postgresql://postgres.PROJECT_REF:MON_MOT_DE_PASSE_SUPABASE@aws-REGION.pooler.supabase.com:5432/postgres"
APP_PIN_PEPPER="LA_MEME_VALEUR_QUE_LORS_DE_LA_MIGRATION"
APP_ENV="cloud"

Ne pas remplacer un APP_PIN_PEPPER déjà utilisé. Les recherches et vérifications de PIN dépendent de cette valeur. Si les PIN fonctionnent actuellement, conserver exactement le secret déjà présent dans Streamlit Cloud.

NexStep utilise désormais réellement cette URL à chaque exécution. En mode cloud, l'application refuse de démarrer si DATABASE_URL manque: elle ne peut donc plus revenir silencieusement vers le fichier SQLite éphémère.

Si une URL est fournie sous la forme postgres://... ou postgresql+psycopg://..., l'application la convertit automatiquement pour psycopg. Les requêtes préparées sont désactivées pour rester compatibles avec les poolers Supabase.

Ne pas publier ces valeurs dans Git, dans un PDF partagé ou dans une capture d'écran.

7. Fermer immédiatement l'accès public Supabase

NexStep se connecte à PostgreSQL depuis le serveur Streamlit et n'utilise ni la clé anon, ni la Data API dans le navigateur. Il ne faut donc créer aucune policy publique.

  1. Dans Supabase, ouvrir SQL Editor.
  2. Ouvrir le fichier database/supabase_security.sql du projet, copier son contenu dans l'éditeur et l'exécuter une fois.
  3. Ouvrir Security Advisor et relancer l'analyse. Les 17 tables NexStep doivent avoir RLS activée.
  4. Option de défense supplémentaire: dans l'intégration Data API, désactiver Enable Data API, puisque NexStep utilise seulement une connexion PostgreSQL privée.

Le script active RLS et retire tous les droits de lecture/écriture aux rôles anon et authenticated. La connexion privée postgres stockée dans les secrets Streamlit continue de fonctionner côté serveur.

Contrôle automatisé facultatif, depuis un terminal où DATABASE_URL est déjà défini:

python scripts/secure_supabase.py --check

Pour appliquer le même fichier SQL depuis le terminal plutôt que depuis SQL Editor:

python scripts/secure_supabase.py --apply

8. Vérifier la sécurité et la persistance

  • Le nombre de leads PostgreSQL doit être au moins égal au nombre SQLite.
  • Les commentaires legacy doivent rester présents.
  • Déployer le commit corrigé, définir un mot de passe agent, puis actualiser la page: NexStep ne doit plus demander la première configuration.
  • Modifier une action réelle ou ajouter un lead utile, puis redémarrer l'application depuis Streamlit Cloud: la modification doit rester visible.
  • Dans Supabase Table Editor, la même modification doit apparaître dans actions, leads ou users.
  • python scripts/secure_supabase.py --check doit afficher OK pour les 17 tables.

SQLite to PostgreSQL Migration Guide

For Streamlit Cloud, copy Supabase's Session pooler URL on port 5432, replace only [YOUR-PASSWORD], and store the complete URL as the root-level DATABASE_URL secret. Also set APP_ENV="cloud" and preserve the exact APP_PIN_PEPPER value used during migration. Changing an existing pepper makes stored PIN lookups and hashes unusable.

NexStep now uses PostgreSQL at runtime and fails closed when cloud mode has no DATABASE_URL. It can no longer silently write to Streamlit Cloud's ephemeral SQLite filesystem.

Emergency Supabase hardening

  1. Open Supabase SQL Editor.
  2. Run the complete database/supabase_security.sql file once.
  3. Rerun Security Advisor; RLS must be enabled on all 17 NexStep tables.
  4. Because NexStep uses a private server connection, optionally disable Enable Data API for an additional security boundary.

Use python scripts/secure_supabase.py --check to audit RLS and public grants. After deploying, set a password or change a real action, restart the Streamlit app, and confirm that the change remains visible both in NexStep and Supabase.
